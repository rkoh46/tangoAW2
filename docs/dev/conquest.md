# Conquest: Select Mode's CONQUEST, roguelike runs of AW2's maps on the Gauntlet's engine (`crate::conquest`, `crate::conquest_reward`)

Select Mode's **CONQUEST** (with the Dual Strike pack, offline, wheel position 5 directly above GAUNTLET: [gauntlet-mode.md](gauntlet-mode.md) "The wheel"). A run is a row of AW2's own two-player Versus maps (3 to 12; **Conquest Run**, run 1, has nine; the table of runs `conquest::RUNS` can hold more: see "Adding a run") (read from the player's ROM), small to large; the survivors and the funds carry over at each map switch, the player picks one **reward** between maps, the enemy CO of each map is **drawn at random** when the run starts, one loss ends the run, and the whole run's score goes to the top-five table (the Gauntlet's record slot). Offline only, like the Gauntlet.
Code: `conquest.rs` (the table of runs, their maps, the mission, the draw, the reward's logic, the mode flag), `conquest_reward.rs` (the reward page's picture), `mode_menu.rs` (the wheel entry), `stage.rs` (`Stub::Reward`, the carry buffer's helpers), `gauntlet_mode.rs` / `gauntlet_ui.rs` (the pictures, the cards, the one-row selector), `custom_campaign.rs` (`defeat_army`, `hidden_alive`), `suspend.rs` (the saved draw). Tests `tools/aw2test/tests/test_conquest.py` (`-k conquest`), driver `tools/aw2test/aw2test/conquest.py`, kit `aw2dev conquest`.

## A mode of its own on the Gauntlet's engine
Conquest and the Gauntlet are two wheel entries and two flows; the engine under them is one (the campaign engine's gauntlet source, `SOURCE` 4: records, Save / Continue, EXP, results, the stage engine, the army screen). How the two are kept apart:
- **The wheel.** Item 10, position 5: label "CONQUEST" (composed from the game's own letters, the Q made from an O), purple, help line "Win every map in a row. One loss ends the run." (run-neutral), and its own Continue / New box ("Continue your saved Conquest run." / "Start a new run. The saved run is dropped.") over a Conquest run saved halfway. A pick stores Campaign's New with the Gauntlet's request (`gauntlet::picked`) and sets the **mode flag** (`conquest::picked`: `STATE + 0x16`, 1 until the next pick of GAUNTLET, whose `gauntlet::picked` clears it).
- **The selector.** The War Room's own SELECT MAP, now showing **a row for each run** ("Conquest Run *", "Long Conquest *": each with its picture, its own record box on R, SELECT flipping through its own maps' pictures) when the flag is set, and only the Gauntlet's twelve maps otherwise (`gauntlet_ui::listed`; the other mode's map-table entries are hidden / given back each frame). A row has a map-table id of its own (the first ids laid out for the campaign's missions, in the runs' order: Survival's last entries 0xEE and 0xEF borrowed while the screen is up, `gauntlet_ui::entries_in_table`), so the Gauntlet's twelve ids are what they were before Conquest Run existed. **Picture slots** (`gauntlet_ui::previews`, `PREVIEW_ROM`: 32 of 0x800 bytes): a run's later maps are cropped from the ROM at run time into slots shared by every run (slot k-1 for map k, the first slots of the room, over the Gauntlet's), because only the highlighted row shows a later map and the two lists are never up together; a map that is not listed gets no picture written (`entries_in_table`), so a 12-map run needs 11 slots whatever the number of runs.
- **The flow.** CONQUEST -> the selector's row of the run -> the army screen (player CO and colour; the CPU card says Random; the help plate names the picked run and its map count: "Long Conquest: 9 maps, a new CO each") -> the run -> AW2's results -> Select Mode with the wheel on CONQUEST (`gauntlet::tick` puts the wheel's remembered position on the mode's entry while the way back runs: the flag says which). B on the selector goes back to the wheel on CONQUEST.
- **Saves.** A run saved from the map menu goes in the Gauntlet's shared slot 12 with the Gauntlet source's tag, and its saved mission byte is the run's mission (run 1's is 12, the next runs' 13...: `conquest::is_mission`, `conquest::run_of_mission`), which also tells **which run** is saved: Continue resumes that run: `gauntlet::saved` (a Gauntlet map's save) is false for it and `conquest::run_saved` true, so CONQUEST's box offers Continue over any Conquest run's save and only that, and GAUNTLET's only over a Gauntlet map's (a BH save is neither's). A new run (the army screen's A) of any Conquest run and a run's end drop only Conquest saves (`gauntlet::drop_own_save`, `suspend::drop_mid_where`). The slot holds one save of the source: saving in one mode replaces the other mode's save, as the BH Campaigns' replace each other's.
- **Records.** In the Gauntlet's top-five table (Flash slot 13 at +0x240, "AWGA", format 2) under the run's own **id**: run 1 is **id 51** (`gauntlet_51`; a nine-map run's score is of another scale than the five-map run's, whose results stay under id 50 (nothing reads them: no migration, nothing lost, they neither show nor block the new ones; the slot they use is one of the table's 32), run 2 is id 52 (`gauntlet_52`). A record id is never reused. EXP and the results screen are the Gauntlet's.

## How it is wired
- **The table of runs** (`conquest::RUNS: &[Run]`; a `Run` is its record key, `title` / `list_title` ("Conquest Run *"), `stage_titles` (the maps after the first), `objective`, `maps: &[Stage]` (3 to `MAX_RUN_MAPS` = 12), `chest` (the war chest's first sum and step), `par_per_map` and `provisional`). Run 1 is Conquest Run (`gauntlet_51`, nine maps), run 2 the PROVISIONAL placeholder "Long Conquest" (`gauntlet_52`; its nine maps `RUN_2_MAPS` are drawn by `aw2dev conquest maps --draft` and the designer will replace them). Helpers: `run_of_key`, `run_of_mission`, `current(core)` (the run the session plays), `Run::offered(k)` (the reward's three units, the eight-step `OFFER_LADDER` spread over the run's rewards, step for step on nine maps), `Run::chest_funds(k)`, `Run::par_days()`.
- **A mission of the Gauntlet's campaign** per run (run 1: `gauntlet_51`: record id 51, never reused; mission index 12 = the first after the Gauntlet's twelve, the runs follow in `RUNS`' order: `gauntlet_mode::def()` appends `conquest::mission(run)` for each, so a new map keeps the kit's `new-map` insertion point and no earlier mission index moves, which keeps saves and records valid). Stage 0 is the mission's own map (`MapSrc::Aw2 { id }`), the later maps are `StageDef`s ([stages.md](stages.md): `Carry::All` capped at 40 units, `funds: None` = the funds carry, the CO and its meter carry).
- **Run 1's maps** (`conquest::RUN_1_MAPS`, `aw2dev conquest maps` checks every run's maps against the ROM), small to large (HQs 20 to 38 cells apart, the same bases for both armies, a land road between the HQs: sea only round the edges or crossed by a causeway / bridge; checked with a flood fill over the tile classes): 0x18 Sabre Range 15x11 (HQs 20 apart), 0x19 Asphalt Maze 15x11 (20), 0x1C Switchback 21x15 (30), 0x22 Piston Dam 26x14 (32), 0x26 Hourglass Isle 16x24 (20: two islands joined by a two-wide causeway), 0x1D Ruby Keys 29x15 (38), 0x21 Vision Bridge 31x24 (27: a bridge across the middle), 0x0E Cube Keys 32x30 (38), 0x75 Mial's Hope 45x28 (37, last: it gives the enemy more cities). The player is army 1 (colour of its pick), the enemy army 2 on **Black Hole's colour** on every map, its own team. The compiled enemy CO is a stand-in (`STAND_IN`); the draw replaces it. A map's picture in the selector is cropped from the ROM at run time into a `PREVIEW_ROM` slot (`gauntlet_ui::aw2_blob`: 8 slots, the Gauntlet's pictures take the others of the 32).
- **The enemy grows**, a step each map: starting funds 3,000 / 4,000 / 5,500 / 7,500 / 9,500 / 12,000 / 14,500 / 17,500 / 22,000, starting force 3 / 3 / 4 / 5 / 5 / 6 / 7 / 7 / 9 units on its properties. Only the first map has a player's force (4 units on its bases); later maps bring the survivors to the cells round the player's HQ (`deploy`: the nearest free cell each can enter).
- **A map is won** by the player taking the enemy HQ or destroying every enemy unit: the enemy HQ is held (`held_hq` / `StageDef::held`: a capture defeats nobody) and a trigger (`Cond::LineFallen` or `ArmyUnitsAtMost { 2, 0 }`) does `Action::NextStage`; the last map's does `Action::Win`. AW2's own defeat of an army with no units and the end check's alive marks are held off on every map but the last (`conquest::keeps_alive`, called from `custom_campaign::defeat_army` and `hidden_alive`), otherwise destroying the enemy would end the whole run in VICTORY. A loss is AW2's normal DEFEAT: results, back to the wheel, the saved run dropped.
- **Score**: par is `Run::par_per_map` days a map (run 1: 8, 72 for the run; `gauntlet_mode::par_days` asks the run); Power divides by the 9 lines and the stage switch carries the player's counters, as for Iron Crown (gauntlet-mode.md "Scoring"). The top five of the run are in the selector's record box under the key.
- **Enemy COs**: `begin_run` (called from `gauntlet_ui::apply`, the army screen's A) shuffles `conquest::pool()` (the roster less Clone Andy, Crumb, Tabitha, Lili and Caulder, who need the skin or a pack of their own: 30 COs, 29 without the player's) with xorshift seeded by AW2's random state word `0x03001FD4` and the console's frame counter, drops the player's CO, and keeps the first as many as the run has maps in the run state (`ENEMIES`, +0x08..+0x13: room for 12, the unused bytes 0; flag +0x15). Map 1's army 2 gets the first at `conquest::map_start` (`ds_campaign::map_start`), the others at `stage::setup` (the stage's `CoSpec` COs overridden for army index 1). Offline only: nothing here is netplay's (`pvp.rs` calls `conquest::tick` only with `mode.is_none()`; the page and the engine's hooks need the Gauntlet's session, which exists only offline, and the wheel patches are only applied offline), so no `SIM_VERSION` bump.
- **Save / Continue**: the run's COs are saved with a run saved from the map menu: `suspend.rs` appends the tail mark **`CQRM`** and 13 bytes (twelve COs, a shorter run's rest 0, and the flag) after AW2's block (after the stage mark on a later map, alone on the first), `applied_ds` puts them back. Which run it is comes from the save's mission byte (not the tail). Run 1's first format, **`CQR9`** with ten bytes (nine COs and the flag), is still read, as run 1's (`conquest::restore` takes either length; `-k old_cqr9`). A run continued on map 3 has the same enemy COs, survivors, funds and enemy army. A **five-map run saved before the run had nine** has the old mark `CQRN` and its stage numbers are other maps now: `conquest::run_saved` does not offer it (`suspend::tail_has`; CONQUEST goes straight to its selector) and a new run's start drops it, so it can never be loaded into the wrong maps.

## The reward (`conquest_reward.rs`, state `conquest::STATE`)
Between maps, after the win and before the next map's fade: the stage engine's swap script has a wait op (`Stub::Reward`, `conquest::reward_wait`) after its trigger scripts; while it holds, the **page** is drawn over the map just won (`ds_coselect::apply` -> `conquest_reward::draw`) with AW2's own white window (red above, blue below), SELECT MAP's pink plate and AW2's font, and `conquest::tick` takes the pad (LEFT / RIGHT choose, A takes, B on the unit page goes back).
1. **War chest** (`Run::chest`): run 1 pays +8,000 funds after map 1, +2,500 more each map (up to 25,500 after map 8), added to the carried funds.
2. **Reinforce**: a second page with three units, better ones later (`OFFER_LADDER`, spread over a run's rewards: on a nine-map run after map 1 Tank / Md Tank / B Copter, then Md Tank / Rockets / Fighter, Md Tank / Rockets / Bomber, Neotank / Rockets / Fighter, Neotank / Rockets / Bomber, Neotank / Megatank / Bomber, Megatank / Neotank / Fighter, Megatank / Neotank / Bomber after map 8); the unit is added to the carry buffer at full HP, ammo and fuel (a full buffer drops its weakest survivor) and lands on a deploy cell with the survivors.
3. **Field repair**: every carried survivor to 10 HP with the type's full ammo and fuel (the unit table's +0x0B and +0x10).
The reward is applied to the **carry buffer** (`stage::carried` / `put_carried` / `set_carried_funds`), so the next map's arrival brings it. State bytes (`conquest::STATE` = 0x0203D0E0, 0x20 bytes, `ram_map`): +0 page, +1 cursor, +2 taken, +3 the map won, +4..+6 the units on offer, +0x08..+0x13 the enemy COs (up to 12), +0x15 drawn, +0x16 the mode flag (CONQUEST's pick).
Pictures: `aw2dev gfx audit --modes conquest --scenes reward_pick` (three looks), `--scenes wheel_and_box,selector_and_army` (the wheel on CONQUEST and its Continue / New box in three looks, the selector with a row for each run and each run's army screen), `--scenes mission_card` (each run's title card), `aw2dev audit text` (the `conquest_*` pages and the wheel's help and box lines: every string whole in its window), `aw2dev conquest sheet [--run N]` (the first turn on each map of run N).

## Its own words
The army screen's banner and the mission card say CONQUEST (`gauntlet_ui::paint_army`, `gauntlet_card::word`); the game's title font has no Q, so `online_art::TitleFont::load` makes one (the O with a diagonal tail, `q_from`; the glyph is the font's last, `TITLE_ORDER`). The wheel's labels have the same lack and the same answer, in the labels' own art (`mode_menu::CONQUEST_LETTERS`).

## Adding a run
A new run is a row of the selector, its own record, saves and maps; no engine change.
1. **Pick the maps.** `aw2dev conquest maps --all` lists every two-player Versus map (HQ distance, bases); `aw2dev conquest maps --draft 0x80,0x70,...` prints a Rust `Stage` draft for each id in play order (HQs, the enemy's force on its own properties grown like run 1's ladder, the player's four starting units on the first map) with a **land-route check** between the HQs (a foot-soldier's flood fill; the Tanks' route is told beside it). Rules: HQs 20+ cells apart, equal (at most one more) bases, a land route, small to large (the first map must fit the picture area, 32 x 22 cells), 3 to 12 maps. Name each `Stage` (the draft says `TODO name`; the names are AW2's map names).
2. **The data**, in `conquest.rs`: a `pub const RUN_n_MAPS: [Stage; N]` (the devkit's `maps` check finds the `RUN_n_MAPS` consts in order, so keep that name), the maps after the first by name in a titles const, and one more `Run { key, title, list_title, stage_titles, objective, maps, chest, par_per_map, provisional }` **appended** to `RUNS`. The key is `gauntlet_NN` with the **next record id never used** (50 was the old five-map run, 51 run 1, 52 run 2: record the key in `the_run_keys_are_record_ids_never_reused`'s list); the id must be unused for ever. Appending gives the run the next mission index after the Gauntlet's twelve (13 for run 2) and a row after the earlier runs: nothing earlier moves. `list_title` ends with the star. Keep the title short: the army screen's help plate says "<title>: N maps, a new CO each" and falls back to the title alone if that is wider than the plate (`gauntlet_ui::HELP_WIDTH`; `aw2dev audit text` checks it).
3. **The harness**: the same rows in `aw2test/conquest.py` (`MAPS_n` and one entry of `RUNS`: title, row text, key, record id, mission, maps, chest, par) and `ga.CONQUEST_RUNS` / `ga.CONQUEST_TITLES` in `aw2test/gauntlet.py` (the selector's rows and ids). `aw2dev conquest maps` must say 0 mismatches.
4. **Check it**: `cargo test -p tango-gamesupport-aw2` (`conquest::tests`: 3 to 12 maps, HQs apart, the enemy grows, keys), `aw2dev conquest start` / `sheet --run N` (the first turn on each map in three looks: look at it), `python3 tools/aw2test/run.py --mode ds -j 4 -k conquest,gauntlet`, `aw2dev audit text`, `aw2dev gfx audit --modes conquest --scenes wheel_and_box,selector_and_army,mission_card,reward_pick`. The selector's picture slots need nothing: a run's later maps use the shared slots (at most 11).
5. A run whose maps are a placeholder says `provisional: true`; the designer swaps `RUN_n_MAPS` (and the titles) and sets it false.

## Changing a map of a run
Edit its `Stage` (id, name, both HQs, the enemy's funds and force on its own properties, the cells being the ROM's), the title in the run's `stage_titles` (and `RUN_n_TITLES`), and the same row in `aw2test/conquest.py`. `aw2dev conquest maps` must say 0 mismatches; then `start`, `sheet --run N`, `-k conquest`.
