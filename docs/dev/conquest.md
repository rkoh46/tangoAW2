# Conquest Run: Select Mode's CONQUEST, a nine-map roguelike run on the Gauntlet's engine (`crate::conquest`, `crate::conquest_reward`)

Select Mode's **CONQUEST** (with the Dual Strike pack, offline, wheel position 5 directly above GAUNTLET: [gauntlet-mode.md](gauntlet-mode.md) "The wheel"). A run is nine of AW2's own two-player Versus maps in a row (read from the player's ROM), small to large; the survivors and the funds carry over at each map switch, the player picks one **reward** between maps, the enemy CO of each map is **drawn at random** when the run starts, one loss ends the run, and the whole run's score goes to the top-five table (the Gauntlet's record slot). Offline only, like the Gauntlet.
Code: `conquest.rs` (the nine maps, the mission, the draw, the reward's logic, the mode flag), `conquest_reward.rs` (the reward page's picture), `mode_menu.rs` (the wheel entry), `stage.rs` (`Stub::Reward`, the carry buffer's helpers), `gauntlet_mode.rs` / `gauntlet_ui.rs` (the pictures, the cards, the one-row selector), `custom_campaign.rs` (`defeat_army`, `hidden_alive`), `suspend.rs` (the saved draw). Tests `tools/aw2test/tests/test_conquest.py` (`-k conquest`), driver `tools/aw2test/aw2test/conquest.py`, kit `aw2dev conquest`.

## A mode of its own on the Gauntlet's engine
Conquest and the Gauntlet are two wheel entries and two flows; the engine under them is one (the campaign engine's gauntlet source, `SOURCE` 4: records, Save / Continue, EXP, results, the stage engine, the army screen). How the two are kept apart:
- **The wheel.** Item 10, position 5: label "CONQUEST" (composed from the game's own letters, the Q made from an O), purple, help line "Nine maps in a row. One loss ends the run.", and its own Continue / New box ("Continue your saved Conquest run." / "Start a new run. The saved run is dropped.") over a Conquest run saved halfway. A pick stores Campaign's New with the Gauntlet's request (`gauntlet::picked`) and sets the **mode flag** (`conquest::picked`: `STATE + 0x16`, 1 until the next pick of GAUNTLET, whose `gauntlet::picked` clears it).
- **The selector.** The War Room's own SELECT MAP, now showing the one row "Conquest Run *" (its picture, the record box on R, SELECT flipping through the later maps' pictures) when the flag is set, and only the Gauntlet's twelve maps otherwise (`gauntlet_ui::listed`; the other mode's map-table entries are hidden / given back each frame). The row keeps its own map-table id (the first of the ids laid out for the campaign's missions, Survival's last entry 0xEF borrowed while the screen is up, `gauntlet_ui::entries_in_table`), so the Gauntlet's twelve ids are what they were before Conquest Run existed.
- **The flow.** CONQUEST -> the one-row selector -> the army screen (player CO and colour; the CPU card says Random) -> the run -> AW2's results -> Select Mode with the wheel on CONQUEST (`gauntlet::tick` puts the wheel's remembered position on the mode's entry while the way back runs: the flag says which). B on the selector goes back to the wheel on CONQUEST.
- **Saves.** A run saved from the map menu goes in the Gauntlet's shared slot 12 with the Gauntlet source's tag, and its saved mission byte is the Conquest mission (12, `conquest::is_mission`): `gauntlet::saved` (a Gauntlet map's save) is false for it and `conquest::run_saved` true, so CONQUEST's box offers Continue only over a Conquest save and GAUNTLET's only over a Gauntlet map's (a BH save is neither's). A new run (the army screen's A) and a run's end drop only their own save (`gauntlet::drop_own_save`, `suspend::drop_mid_where`). The slot holds one save of the source: saving in one mode replaces the other mode's save, as the BH Campaigns' replace each other's.
- **Records.** In the Gauntlet's top-five table (Flash slot 13 at +0x240, "AWGA", format 2) under **id 51** (`gauntlet_51`): a nine-map run's score is of another scale than the five-map run's, whose results stay under id 50 (nothing reads them: no migration, nothing lost, they neither show nor block the new ones; the slot they use is one of the table's 32). EXP and the results screen are the Gauntlet's.

## How it is wired
- **A mission of the Gauntlet's campaign** (`gauntlet_51`: record id 51, never reused; mission index = the last of `gauntlet_mode::def()`, pushed after the maps so a new map keeps the kit's `new-map` insertion point). Stage 0 is the mission's own map (`MapSrc::Aw2 { id }`), the four later maps are `StageDef`s ([stages.md](stages.md): `Carry::All` capped at 40 units, `funds: None` = the funds carry, the CO and its meter carry).
- **Maps** (`conquest::MAPS`, `aw2dev conquest maps` checks them against the ROM), small to large (HQs 20 to 38 cells apart, the same bases for both armies, a land road between the HQs: sea only round the edges or crossed by a causeway / bridge; checked with a flood fill over the tile classes): 0x18 Sabre Range 15x11 (HQs 20 apart), 0x19 Asphalt Maze 15x11 (20), 0x1C Switchback 21x15 (30), 0x22 Piston Dam 26x14 (32), 0x26 Hourglass Isle 16x24 (20: two islands joined by a two-wide causeway), 0x1D Ruby Keys 29x15 (38), 0x21 Vision Bridge 31x24 (27: a bridge across the middle), 0x0E Cube Keys 32x30 (38), 0x75 Mial's Hope 45x28 (37, last: it gives the enemy more cities). The player is army 1 (colour of its pick), the enemy army 2 on **Black Hole's colour** on every map, its own team. The compiled enemy CO is a stand-in (`STAND_IN`); the draw replaces it. A map's picture in the selector is cropped from the ROM at run time into a `PREVIEW_ROM` slot (`gauntlet_ui::aw2_blob`: 8 slots, the Gauntlet's pictures take the others of the 32).
- **The enemy grows**, a step each map: starting funds 3,000 / 4,000 / 5,500 / 7,500 / 9,500 / 12,000 / 14,500 / 17,500 / 22,000, starting force 3 / 3 / 4 / 5 / 5 / 6 / 7 / 7 / 9 units on its properties. Only the first map has a player's force (4 units on its bases); later maps bring the survivors to the cells round the player's HQ (`deploy`: the nearest free cell each can enter).
- **A map is won** by the player taking the enemy HQ or destroying every enemy unit: the enemy HQ is held (`held_hq` / `StageDef::held`: a capture defeats nobody) and a trigger (`Cond::LineFallen` or `ArmyUnitsAtMost { 2, 0 }`) does `Action::NextStage`; the last map's does `Action::Win`. AW2's own defeat of an army with no units and the end check's alive marks are held off on every map but the last (`conquest::keeps_alive`, called from `custom_campaign::defeat_army` and `hidden_alive`), otherwise destroying the enemy would end the whole run in VICTORY. A loss is AW2's normal DEFEAT: results, back to the wheel, the saved run dropped.
- **Score**: par is 8 days a map, 72 for the run (`gauntlet_mode::PAR_OVERRIDES`); Power divides by the 9 lines and the stage switch carries the player's counters, as for Iron Crown (gauntlet-mode.md "Scoring"). The top five of the run are in the selector's record box under the key.
- **Enemy COs**: `begin_run` (called from `gauntlet_ui::apply`, the army screen's A) shuffles `conquest::pool()` (the roster less Clone Andy, Crumb, Tabitha, Lili and Caulder, who need the skin or a pack of their own: 30 COs, 29 without the player's) with xorshift seeded by AW2's random state word `0x03001FD4` and the console's frame counter, drops the player's CO, and keeps the first nine in the run state (`ENEMIES`, +0x08..+0x10; flag +0x15). Map 1's army 2 gets the first at `conquest::map_start` (`ds_campaign::map_start`), the others at `stage::setup` (the stage's `CoSpec` COs overridden for army index 1). Offline only: nothing here is netplay's (`pvp.rs` calls `conquest::tick` only with `mode.is_none()`; the page and the engine's hooks need the Gauntlet's session, which exists only offline, and the wheel patches are only applied offline), so no `SIM_VERSION` bump.
- **Save / Continue**: the nine COs are saved with a run saved from the map menu: `suspend.rs` appends the tail mark `CQR9` and ten bytes (nine COs and the flag) after AW2's block (after the stage mark on a later map, alone on the first), `applied_ds` puts them back. A run continued on map 3 has the same enemy COs, survivors, funds and enemy army. A **five-map run saved before the run had nine** has the old mark `CQRN` and its stage numbers are other maps now: `conquest::run_saved` does not offer it (`suspend::tail_has`; CONQUEST goes straight to its selector) and a new run's start drops it, so it can never be loaded into the wrong maps.

## The reward (`conquest_reward.rs`, state `conquest::STATE`)
Between maps, after the win and before the next map's fade: the stage engine's swap script has a wait op (`Stub::Reward`, `conquest::reward_wait`) after its trigger scripts; while it holds, the **page** is drawn over the map just won (`ds_coselect::apply` -> `conquest_reward::draw`) with AW2's own white window (red above, blue below), SELECT MAP's pink plate and AW2's font, and `conquest::tick` takes the pad (LEFT / RIGHT choose, A takes, B on the unit page goes back).
1. **War chest**: +8,000 funds after map 1, +2,500 more each map (up to 25,500 after map 8), added to the carried funds.
2. **Reinforce**: a second page with three units, better ones later (after map 1 Tank / Md Tank / B Copter, then Md Tank / Rockets / Fighter, Md Tank / Rockets / Bomber, Neotank / Rockets / Fighter, Neotank / Rockets / Bomber, Neotank / Megatank / Bomber, Megatank / Neotank / Fighter, Megatank / Neotank / Bomber after map 8); the unit is added to the carry buffer at full HP, ammo and fuel (a full buffer drops its weakest survivor) and lands on a deploy cell with the survivors.
3. **Field repair**: every carried survivor to 10 HP with the type's full ammo and fuel (the unit table's +0x0B and +0x10).
The reward is applied to the **carry buffer** (`stage::carried` / `put_carried` / `set_carried_funds`), so the next map's arrival brings it. State bytes (`conquest::STATE` = 0x0203D0E0, 0x20 bytes, `ram_map`): +0 page, +1 cursor, +2 taken, +3 the map won, +4..+6 the units on offer, +0x08..+0x10 the enemy COs, +0x15 drawn, +0x16 the mode flag (CONQUEST's pick).
Pictures: `aw2dev gfx audit --modes conquest --scenes reward_pick` (three looks), `--scenes wheel_and_box,selector_and_army` (the wheel on CONQUEST and its Continue / New box in three looks, the one-row selector and the army screen), `aw2dev audit text` (the `conquest_*` pages and the wheel's help and box lines: every string whole in its window), `aw2dev conquest sheet`.

## Its own words
The army screen's banner and the mission card say CONQUEST (`gauntlet_ui::paint_army`, `gauntlet_card::word`); the game's title font has no Q, so `online_art::TitleFont::load` makes one (the O with a diagonal tail, `q_from`; the glyph is the font's last, `TITLE_ORDER`). The wheel's labels have the same lack and the same answer, in the labels' own art (`mode_menu::CONQUEST_LETTERS`).

## Adding or changing a map
1. `aw2dev conquest maps --all` lists every two-player Versus map (HQ distance, bases): pick one with HQs 20+ cells apart, equal bases, no sea between.
2. Edit its `Stage` in `conquest::MAPS` (id, name, both HQs, the enemy's funds and force on its own properties, the cells being the ROM's), the title in `mission()`'s `stage_titles`, and the same row in `aw2test/conquest.py` `MAPS`. `aw2dev conquest maps` must say 0 mismatches.
3. Run `aw2dev conquest start`, `sheet`, then `-k conquest` and look at the pictures. More than nine maps need `STAGES`, the `PREVIEW_ROM` slots (32 in all: `gauntlet_ui::previews`) and `conquest::offered` / `chest_funds` rows.
