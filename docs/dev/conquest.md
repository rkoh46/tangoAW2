# Conquest Run: the Gauntlet's five-map roguelike run (`crate::conquest`, `crate::conquest_reward`)

The first row of the Gauntlet's map selector, **Conquest Run \***. A run is five of AW2's own two-player Versus maps in a row (read from the player's ROM), small to large; the survivors and the funds carry over at each map switch, the player picks one **reward** between maps, the enemy CO of each map is **drawn at random** when the run starts, one loss ends the run, and the whole run's score goes to the Gauntlet's records. Offline only, like the Gauntlet.
Code: `conquest.rs` (the five maps, the mission, the draw, the reward's logic), `conquest_reward.rs` (the reward page's picture), `stage.rs` (`Stub::Reward`, the carry buffer's helpers), `gauntlet_mode.rs` / `gauntlet_ui.rs` (the row, the pictures, the cards), `custom_campaign.rs` (`defeat_army`, `hidden_alive`), `suspend.rs` (the saved draw). Tests `tools/aw2test/tests/test_conquest.py` (`-k conquest`), driver `tools/aw2test/aw2test/conquest.py`, kit `aw2dev conquest`.

## How it is wired
- **A mission of the Gauntlet's campaign** (`gauntlet_50`: record id 50, never reused; mission index = the last of `gauntlet_mode::def()`, pushed after the maps so a new map keeps the kit's `new-map` insertion point). Stage 0 is the mission's own map (`MapSrc::Aw2 { id }`), the four later maps are `StageDef`s ([stages.md](stages.md): `Carry::All` capped at 40 units, `funds: None` = the funds carry, the CO and its meter carry). Records, Save / Continue, EXP and the results screen are the Gauntlet's ([gauntlet-mode.md](gauntlet-mode.md)).
- **Maps** (`conquest::MAPS`, `aw2dev conquest maps` checks them against the ROM): 0x18 Sabre Range 15x11, 0x1C Switchback 21x15, 0x22 Piston Dam 26x14, 0x0E Cube Keys 32x30, 0x75 Mial's Hope 45x28. HQs 20 to 38 cells apart, the same bases for both armies (Mial's Hope gives the enemy more cities: the last map is the hardest), no sea to cross. The player is army 1 (colour of its pick), the enemy army 2 on **Black Hole's colour** on every map, its own team. The compiled enemy CO is a stand-in (`STAND_IN`); the draw replaces it. A map's map picture in the selector is cropped from the ROM at run time into a `PREVIEW_ROM` slot (`gauntlet_ui::aw2_blob`).
- **The enemy grows**: its starting funds (3,000 / 6,000 / 10,000 / 15,000 / 22,000) and its starting force (3 / 4 / 6 / 7 / 9 units on its properties) grow each map. Only the first map has a player's force (4 units on its bases); later maps bring the survivors to the cells round the player's HQ (`deploy`: the nearest free cell each can enter).
- **A map is won** by the player taking the enemy HQ or destroying every enemy unit: the enemy HQ is held (`held_hq` / `StageDef::held`: a capture defeats nobody) and a trigger (`Cond::LineFallen` or `ArmyUnitsAtMost { 2, 0 }`) does `Action::NextStage`; the last map's does `Action::Win`. AW2's own defeat of an army with no units and the end check's alive marks are held off on every map but the last (`conquest::keeps_alive`, called from `custom_campaign::defeat_army` and `hidden_alive`), otherwise destroying the enemy would end the whole run in VICTORY. A loss is AW2's normal DEFEAT: results, back to the wheel, the saved run dropped.
- **Score**: par is 8 days a map, 40 for the run (`gauntlet_mode::PAR_OVERRIDES`); Power divides by the 5 lines and the stage switch carries the player's counters, as for Iron Crown (gauntlet-mode.md "Scoring"). The top five of the run are in the selector's record box under the key.
- **Enemy COs**: `begin_run` (called from `gauntlet_ui::apply`, the army screen's A) shuffles `conquest::pool()` (the roster less Clone Andy, Crumb, Tabitha, Lili and Caulder, who need the skin or a pack of their own) with xorshift seeded by AW2's random state word `0x03001FD4` and the console's frame counter, drops the player's CO, and keeps the first five in the run state (`ENEMIES`, +0x10; flag +0x15). Map 1's army 2 gets the first at `conquest::map_start` (`ds_campaign::map_start`), the others at `stage::setup` (the stage's `CoSpec` COs overridden for army index 1). Offline only: nothing here is netplay's (`pvp.rs` calls `conquest::tick` only with `mode.is_none()`; the page and the engine's hooks need the Gauntlet's session, which exists only offline), so no `SIM_VERSION` bump.
- **Save / Continue**: the five COs are saved with a run saved from the map menu: `suspend.rs` appends the tail mark `CQRN` and six bytes after AW2's block (after the stage mark on a later map, alone on the first), `applied_ds` puts them back. A run continued on map 3 has the same enemy COs, survivors, funds and enemy army.

## The reward (`conquest_reward.rs`, state `conquest::STATE`)
Between maps, after the win and before the next map's fade: the stage engine's swap script has a wait op (`Stub::Reward`, `conquest::reward_wait`) after its trigger scripts; while it holds, the **page** is drawn over the map just won (`ds_coselect::apply` -> `conquest_reward::draw`) with AW2's own white window (red above, blue below), SELECT MAP's pink plate and AW2's font, and `conquest::tick` takes the pad (LEFT / RIGHT choose, A takes, B on the unit page goes back).
1. **War chest**: +10,000 funds after map 1, +5,000 more each map (15,000, 20,000, 25,000), added to the carried funds.
2. **Reinforce**: a second page with three units, better ones later (after map 1 Tank / Md Tank / B Copter, then Md Tank / Rockets / Fighter, Neotank / Rockets / Bomber, Megatank / Neotank / Bomber); the unit is added to the carry buffer at full HP, ammo and fuel (a full buffer drops its weakest survivor) and lands on a deploy cell with the survivors.
3. **Field repair**: every carried survivor to 10 HP with the type's full ammo and fuel (the unit table's +0x0B and +0x10).
The reward is applied to the **carry buffer** (`stage::carried` / `put_carried` / `set_carried_funds`), so the next map's arrival brings it. State bytes (`conquest::STATE` = 0x0203D0E0, 0x20 bytes, `ram_map`): +0 page, +1 cursor, +2 taken, +3 the map won, +4..+6 the units on offer, +0x10..+0x14 the enemy COs, +0x15 drawn.
Pictures: `aw2dev gfx audit --modes conquest --scenes reward_pick` (three looks), `aw2dev audit text` (the `conquest_*` pages: every string whole in its window), `aw2dev conquest sheet`.

## Tests (`-k conquest`)
Row first with its title; a run starts (forces, funds, colours); a won map carries survivors (count, kind, HP) and funds; destroying every enemy unit also moves on; a defeat ends the run with no record; a full run's win writes the record row (and Flash slot 13); the reward page opens over the map just won (pad taken); the war chest, the free unit (units page, back with B) and the field repair do what they say (the repair on the arrival, the chest's non-healing read from the carry buffer); the enemy COs are drawn (five different, never the player's, from the usable roster, each map has its own, a later run draws others); Save / Continue on map 3 and on map 1 keep the draw, the armies and the funds; `conquest_tool_start`, `conquest_pictures` (the kit's commands). Cargo: `conquest::tests` (maps, rewards, the draw), `conquest_reward::tests` (layout), `gauntlet_ui::tests` (pictures), `ram_map` (overlap).

## Adding or changing a map
1. `aw2dev conquest maps --all` lists every two-player Versus map (HQ distance, bases): pick one with HQs 20+ cells apart, equal bases, no sea between.
2. Edit its `Stage` in `conquest::MAPS` (id, name, both HQs, the enemy's funds and force on its own properties, the cells being the ROM's), the title in `mission()`'s `stage_titles`, and the same row in `aw2test/conquest.py` `MAPS`. `aw2dev conquest maps` must say 0 mismatches.
3. Run `aw2dev conquest start`, `sheet`, then `-k conquest` and look at the pictures. More than five maps need `STAGES`, the `PREVIEW_ROM` slots (32 in all: `gauntlet_ui::previews`) and `conquest::offered` / `chest_funds` rows.
