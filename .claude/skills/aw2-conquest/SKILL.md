name: aw2-conquest
description: Work on Conquest, Select Mode's CONQUEST entry (a table of roguelike runs on the Gauntlet's engine, Conquest Run first: AW2 Versus maps, carry-over, a reward between maps, a random enemy CO a map, Save / Continue); add a run, change a map, a reward, the enemy draw or the wheel entry, and check it

Read docs/dev/conquest.md first (the wiring, the state bytes, the tests). Code: `tango-gamesupport-aw2/src/conquest.rs` (`RUNS`, the runs' maps, mission, draw, reward logic, the mode flag), `conquest_reward.rs` (the page), the stage engine's `Stub::Reward` in `stage.rs`, `mode_menu.rs` (the wheel entries: label, help line, Continue / New box, and CONTINUE, present only with a saved run), `gauntlet_ui.rs` (`listed`: the selector's rows, one a run; `previews`: the runs' shared picture slots).

1. Build (`./aw2dev build --examples`), then `./aw2dev conquest maps`: every run's maps read from the ROM against the constants in `conquest.rs` (exit 1 on a mismatch). `./aw2dev conquest maps --all` lists every two-player Versus map with its HQ distance and bases to choose from (keep HQs 20+ cells apart, equal bases, no sea to cross); `./aw2dev conquest maps --draft 0x80,0x70,...` drafts the Rust `Stage`s for ids in play order with a land-route check.
2. Run it: `./aw2dev conquest start [--co N]` (a picture of each screen, fails if one is missing) and `./aw2dev conquest sheet [--run N]` (the reward page, the unit page and each map's first turn of run N in the three looks, one PNG: look at it).
3. Tests: `./aw2dev conquest test` (`-k conquest`), then `python3 tools/aw2test/run.py -k conquest,gauntlet_mode,gauntlet_wheel,wheel --mode ds -j 6`. Every run is a mission of the Gauntlet's campaign (the last ones of `def()`, in `RUNS`' order: run 1 is `ga.CONQUEST_MISSION` = 12, run 2 is 13) that the Gauntlet's selector does not list; the CONQUEST wheel entry (position 5, item 10) sets the mode flag and lists a row for each. Drive run N with `cq.Conquest(g, run=N-1)`.
4. A new reward or a changed text: `conquest_reward.rs` draws with AW2's windows and plate only; run `./aw2dev audit text` (the `conquest_*` pages) and `./aw2dev gfx audit --modes conquest` and look at the sheets in all three looks (AW2, Dual Strike + tilt, Dual Strike flat).
5. New EWRAM goes in `ram_map.rs` (the overlap test), nothing of a Versus / online battle's simulation may change (no `SIM_VERSION` bump: the mode is offline).
6. **CONTINUE** is the wheel's optional tenth entry (position 6, directly above CONQUEST) while a Conquest run is saved (`mode_menu`: `layout`, `write_layout`, `change_layout`, `TABLE_SAVED`; docs/dev/gauntlet-mode.md "The wheel"). In tests use `saves.position(e, "continue")` / `saves.wheel_to(e, "campaign")` (they read the ROM image's table, so positions above CONQUEST follow the save) and `cq.Conquest(g).open_continue()`; `-k conquest_continue` covers it. A change to the wheel's count, a wheel entry or the label art: check `wheel_and_box` in the three looks (the wheel with and without a save, CONTINUE and CONQUEST selected) and the transitions between the entries frame by frame (the big label's colours on its way to the centre).
7. The wheel entry's pictures: `./aw2dev gfx audit --modes conquest --scenes wheel_and_box,selector_and_army` (three looks; look at the label, the box and the help line; upscale 3x and look at the small labels' tiles and colours: OBJ bank 15 is shared with the title badge's colours 4, 13, 14).

## Adding a run
Read docs/dev/conquest.md "Adding a run". In short: `aw2dev conquest maps --all` / `--draft`, a `RUN_n_MAPS` const and one `Run` appended to `conquest::RUNS` (a never-used `gauntlet_NN` record key; never reorder or insert before an existing run: the mission index and the saves follow the order), the same rows in `aw2test/conquest.py` (`RUNS`) and `ga.CONQUEST_RUNS` / `CONQUEST_TITLES`, then `conquest sheet --run N`, `-k conquest,gauntlet`, `aw2dev audit text` and `gfx audit --modes conquest` (the selector scene shows every run's row and maps). A saved run is told apart by its mission byte, so continuing needs nothing more; its draw is saved in the `CQRM` tail (12 COs; `CQR9` still reads as run 1).
